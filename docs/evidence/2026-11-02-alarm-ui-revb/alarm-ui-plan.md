# Plan — HMI alarms readable by the operator (LCP-01, KTP400 Comfort, TIA V15.1)

## Context
- 22 discrete alarms already imported into TIA from `build/hmi/Alarms_LCP01.xlsx`, generated by
  `tools/build_alarms.py` from `HMI_ALARMS` in `tools/build_blocks.py` (word, bit, PLC source, text, clears, ref).
- Today: all 22 use class `No Acknowledgement`; the Info text reads like an engineering note
  ("Clears: RESET with all scrubber trip causes healthy. Source: C03 / C06a (PH proposal: cause memory)").
- User feedback (the operator/owner): info text must be understandable by a non-engineer, with no C&E
  references; the alarm view should drop the Acknowledgement column and use colours.
- Openness V15.1 has no API for Comfort alarms or for the alarm view (checked in the DLL). Alarms go in
  through TIA's own Import button (Excel); the alarm view is configured by hand in TIA.
- Decision D4 (0007): no acknowledgement on the HMI; RESET is the door button S2.

## Changes

### A. Alarm text and info text (Sol, in `tools/build_alarms.py`)
1. Alarm text (one line, shown in the list): short, plain English, starts with the equipment
   (`Scrubber`, `BR01`, `BR02`, `TK01`…), keeps the instrument tag where it helps the field
   (e.g. `PSH-101`). Max ~45 characters so it fits the 4.3" view.
2. Info text (the "?" button): 2–3 short sentences for an operator, no C&E/rule IDs:
   - what happened (in plain words),
   - what the panel did as a result (e.g. "Both burners stopped", "Burners keep running"),
   - what to do to clear it (e.g. "Fix the cause, then press RESET on the panel door, then START").
   Facts must come from the current sources: `deliverables/PH-LCP-01-CE_RevA.xlsx` (C&E Matrix
   columns: effect and reset), `docs/التشغيل.md`, and the clear rule already in `HMI_ALARMS`.
   Burner lockout: the reset of the burner control box is local at the burner (F49 in docs/ISSUES.md).
3. Keep the engineering reference (C&E row) out of the panel but traceable: put it in a comment
   column of the generator data (not exported), so docs and code still map one-to-one.
4. Operator texts live in ONE table in `build_alarms.py` keyed by (word, bit); the script fails if a
   key in `HMI_ALARMS` has no operator text or vice versa.

### B. Two classes (Sol, in `tools/build_alarms.py`)
- **Faults** (red): anything that stops something or needs RESET → class `No Acknowledgement`
  (built-in, "Alarm without acknowledgement", background red).
- **Warnings** (yellow): information that clears by itself and stops nothing → class `Warnings`
  (built-in, "Alarm without acknowledgement").
  Proposed Warnings: Common x4 (LSH-102 high level: drain opens, normal control), Common x5 (setting
  rejected), BR01 x6 / BR02 x6 (tank level low: burner held, restarts by itself).
  Everything else is a Fault.

### C. Manual steps in TIA (user, guided; not scriptable in V15.1)
1. Alarm classes tab: set `Warnings` background to yellow (incoming), keep `No Acknowledgement` red.
2. Alarm view → Properties → columns: hide `No.`, `Date`, `Acknowledgement group`; keep `Time`,
   `Text` (and `Status` only if room). Enable whatever V15.1 calls "use alarm class colours".
3. Alarm view → Toolbar: hide `Acknowledge` and `Loop-in alarm`; keep `Info text`.
4. Delete the 22 alarms, re-import the new Excel, save.

### D. Verification
- `py tools/build_alarms.py` runs; every key covered; text lengths reported.
- After import, on the panel simulator with PLCSIM (`tools/plcsim/demo.py`): one Fault (psh) shows red
  with the new info text; one Warning (lsh) shows yellow and clears by itself; E-STOP shows and clears
  after release + RESET.
- Evidence file in `docs/evidence/`, STATE updated, commit.

## Not in this plan

- Any PLC change.
