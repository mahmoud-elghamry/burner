1. **HIGH — B: Three proposed Warnings violate the stated classification rule.** `Common.x5` is latched until RESET; restoring the previous setting does not clear it. `BR01.x6` and `BR02.x6` remove heat and stage requests when tank level falls. **Fix:** under B’s existing definition, use **21 Faults and one Warning (`Common.x4`)**. All other proposed Fault assignments are consistent, including `Common.x7`, which requires RESET without itself commanding a shutdown. Red must not imply that every alarm puts a burner into PLC `FAULT`. [PLC evidence](D:/tasks/burner/tools/build_blocks.py:367)

2. **HIGH — A2/B: “Restarts by itself” is wrong without mode and permission conditions.** Low-level alarms clear automatically, but burner restart is separate: AUTO resumes only with retained enable, heat demand and healthy permissives; MAN requires another START after the interrupted cycle. **Fix:** explicitly distinguish alarm clearance from restart, and state the AUTO/MAN difference. [Burner ladder generator](D:/tasks/burner/tools/build_blocks.py:618)

3. **HIGH — A2: The November 2 drain behavior needs explicit text requirements.** Merely referring the writer to the sources leaves conflicting older statements available, including AGENTS’ drain-NO rule. **Fix:** require these facts in the relevant texts:
   - PSH commands flare open and suction closed; it does not change drain control.
   - LSHH commands suction closed; it does not trip the flare. Drain follows either high-level signal.
   - Drain opening/closing uses configured delays, defaults 3/5 seconds. The LSH alarm itself follows the input immediately.
   - Drain is **NC**, inhibited during latched E-STOP and drain timeout, but can operate before scrubber RESET after power-up.
   
   These are supported by the [current ladder](D:/tasks/burner/tools/build_blocks.py:414) and [C&E rows C01–C05](D:/tasks/burner/deliverables/PH-LCP-01-CE_RevA.xlsx).

4. **HIGH — A2: Generic RESET → START instructions conceal different reset effects.** Drain-timeout RESET can immediately restore an existing drain demand; it does **not** require healthy level switches. Scrubber RESET can restore valve commands. Setting-rejection RESET only clears its indication; the previous value was already restored. **Fix:** specify clearance and resulting action per alarm, particularly: investigate the prolonged drain demand before RESET, because RESET can reopen it. Retain the correct lockout sequence: investigate/clear the burner-box fault locally, then door S2, then that burner’s START. F49 provides no implemented remote-reset alternative. [Reset logic](D:/tasks/burner/tools/build_blocks.py:441), [F49](D:/tasks/burner/docs/ISSUES.md:66)

5. **HIGH — A2: The example effect wording can overstate what the PLC knows.** “Burners keep running” is not guaranteed during scrubber trips: their own controls can stop them. “Burner stopped” is particularly misleading for **RUN without request**. Valve positions have no feedback. **Fix:** describe commands precisely—“The PLC leaves burner requests unchanged,” “Heat request removed,” and “Drain commanded closed.” Identify latched trip records as such, rather than asserting that the initiating condition remains present. [Operating rules](D:/tasks/burner/docs/التشغيل.md), [RUN-without-request logic](D:/tasks/burner/tools/build_blocks.py:626)

6. **MEDIUM — A2: One supplied clearing rule is not literally the PLC condition.** `Common.x7` says RESET when the switches “agree,” but the rung permits reset whenever **LSHH-high without LSH-high is absent**. Normal intermediate level—LSH high, LSHH healthy—also permits reset despite unequal signals. **Fix:** use “After the inconsistent level indication has cleared, press RESET”; record the source-wording discrepancy rather than reproducing “both switches agree.” [Exact rung](D:/tasks/burner/tools/build_blocks.py:447)

Also explicitly enable both classes in the view; importing a Warning does not establish that the view displays it. **Fix:** configure incoming colors deliberately, verify both classes require no acknowledgement, and test selection highlighting and outgoing colors if history is shown. The global switch is visible in Siemens’ [V15.1 documentation](https://support.industry.siemens.com/cs/attachments/109763525/Create_MyHMI_WinCC_config_man_1218_en-US.pdf); the corresponding [Comfort control documentation](https://docs.tia.siemens.cloud/r/en-us/v20/creating-screens-basic-panels-panels-comfort-panels-rt-advanced-rt-professional/display-and-operating-elements-basic-panels-panels-comfort-panels-rt-advanced-rt-professional/objects-basic-panels-panels-comfort-panels-rt-advanced-rt-professional/alarm-view-as-of-v13-basic-panels-panels-comfort-panels-rt-advanced) confirms class selection.
