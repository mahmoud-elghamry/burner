القواعد التي وافق عليها، في حدود العرض الذي رد عليه:

1. التحكم بأعلى قراءة من حساسي كل تانك؛ مثال 55°C و72°C يعني إيقاف البيرنر عند SP=70°C.
2. MAN دورة واحدة تنتهي عند حد الإيقاف، ثم يلزم START جديد؛ AUTO يعيد التشغيل عند حد العودة.
3. بعد انقطاع الكهرباء وعودتها، البيرنرات تنتظر START جديدًا حتى لو الوضع AUTO.
4. تريب scrubber يفتح flare وdrain ويقفل suction، ولا يزيل PLC طلب تشغيل البيرنرات.
   هذا القرار مسجل سابقًا في `docs/evidence/2026-10-26-inputs-read.md`، جدول إجابات المهندس زين.
   المستخدم أكد الآن أن السجل يعكس قراره السابق؛ لا يُعاد طرحه كسؤال مفتوح.

هذه موافقة داخلية مباشرة على القواعد الأربع؛ لا ننسبها تلقائيًا للعميل أو نعممها على بقية القرارات.

## ما فُحص بعد إخطار المستخدم بإصلاح الأدوات

- إصلاحات الشات الآخر موجودة في commit `54bbb8f`، قبل أي تعديل أدوات من هذه الجلسة.
- تمت مراجعة diff: تجميع نتائج الهاردوير والسوفتوير والبلوكات، وفحص State مع ErrorCount،
  ومنع الحفظ عند الفشل وإرجاع exit 1؛ وفحص البلوكات داخل الجروبات؛ ورفض Export وList إذا كان TIA مفتوحًا.
- تم فحص السكريبتات الأربعة بـPowerShell Parser: أربع نتائج `PARSE_OK` دون أخطاء.
- تم استخراج C# المضمن دون تشغيل السكريبتات، وتجميعه بـAdd-Type في Windows PowerShell
  على Siemens.Engineering.dll الخاصة بـV15.1: نجح لكل من Compile-Project وApply-Blocks.
- لم تُفتح جلسة Openness، ولم يحدث import أو compile لمشروع PLC أو اختبار PLCSIM.
- لم تُعدَّل الأدوات في هذه الجلسة. يلزم اختبار سلوكها على مشروع TIA؛ نجاح تجميع
  C# يؤكد توافقه مع API المتاحة، ولا يثبت نتائج تشغيل المشروع أو منطق PLC.
- أثناء الفحص ظهر `tia/Burner/Burner.ap15_1` وعمليات TIA قائمة من عمل متوازٍ؛ لم نفتح المشروع
  أو نغلق TIA أو نغيّر ملفاته. هذا جرد وجود فقط، وليس تحققًا من محتوى المشروع الجديد.
