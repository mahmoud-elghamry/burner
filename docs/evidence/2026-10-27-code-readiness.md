# 2026-10-27 — الحالة قبل كتابة الكود

## فحص فعلي في هذه الجلسة

- جرد tia: `.gitkeep` فقط؛ لا يوجد مشروع TIA أو برنامج PLC في هذا المسار.
- ملفا Siemens.Engineering.dll وSiemens.Engineering.Hmi.dll موجودان في PublicAPI V15.1.
- فحص عضوية جروب Openness داخل توكن المستخدم الحالي أعاد `True`.
- عدد عمليات Siemens.Automation.Portal وقت الفحص: `0`.
- هذه فحوص جاهزية فقط؛ لم تُفتح جلسة Openness ولم يحدث import أو compile أو PLCSIM.

## ما يلزم قبل التنفيذ

1. مراجعة مختصرة لوصف التشغيل الذي أعده الإيجنت، خصوصًا اختيار MAX، ومعنى MAN، والسلوك
   بعد الكهرباء وRESET وتغيير الوضع، وعلاقة تريب scrubber بطلب تشغيل البيرنرين. الرسم أساس
   التوصيلات، والتفاصيل التشغيلية التي لا يحددها تحتاج تثبيتًا قبل أن تصبح منطقًا تنفيذيًا.
2. إنشاء مشروع TIA وضبط الهاردوير والعناوين؛ قراءة firmware الـCPU قبل تثبيت تكوين العتاد الفعلي.
3. إصلاح F28/F29 قبل أول استخدام للأدوات: سكريبت الكومبايل يتجاهل نتيجة الهاردوير عند تقرير
   الحفظ، ويفحص ErrorCount فقط للسوفتوير؛ سكريبت التصدير يحذر عند فتح TIA ولا يرفض، وList-Blocks
   لا يختبر ذلك. هذا تأكيد بقراءة الملفات؛ لم تُجرَّب الأدوات على مشروع هنا.
4. تعريف RUN وفق الإشارة الموصلة في الرسم ومعالجة F35 في وصف التشغيل؛ لا يلزم من المستخدم
   تحويله لقياس لهب أو تغيير التسليك. وتوحيد المشتقات والتاجات على القواعد التي تثبت.

## ما حُسم وما يأتي لاحقًا

- أولوية الرسم، واتباع واجهة BR02 المرسومة، وأصل اختيار الهيستريسيس مؤكدة مباشرة من المستخدم؛
  مصدرها `docs/evidence/2026-10-27-user-drawing-priority.md`. لا نعيد طرح الأرقام كعائق للبدء.
- هيكل التنفيذ المكتوب في القرار 0006: LAD، وFB Burner بنسختين، وFB Scrubber، وOutputs لكتابة المخارج.
- إثبات التنفيذ يأتي بعد الكتابة: import ثم compile موثق ثم اختبارات PLCSIM لكل صف وسلوك.
  قطبية الحساسات وتشخيص TC وواجهات البيرنر تُثبت كذلك على العتاد؛ لا يستبدلها نجاح المحاكاة.
- لم تُكتب أو تُعدّل برامج PLC في هذا التحديث؛ هو بيان جاهزية، وليس اعتمادًا وظيفيًا.
